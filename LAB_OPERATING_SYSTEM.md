# Code Gym Developmental Systems Lab - Operating System

## Mission
Build and falsify a rigorous theory of developmental state completion and counterfactual developmental tomography, then publish only what survives explicit attempts at refutation.

## Research lanes

### Lane M - Mathematics and theory
Formalize connected causal fibers, counterfactual embedding dimension, intervention-indexed predictive-state equivalence, stability, and identifiability. Every proposed theorem must be paired with assumptions and a counterexample search.

### Lane A - Novelty and literature attack
Try to show our ideas already exist. Search developmental biology, control/observability, causal inference, predictive-state representations, active experimental design, Reeb/persistent topology, neutral networks and evo-devo. The output is a novelty boundary, not marketing.

### Lane B - Prospective biology
Design blinded living-system tests with frozen algorithms, preregistered outcomes, negative controls, matched baseline morphology, and random/equal-cost perturbation baselines.

### Lane C - Funding
Track only live, authoritative opportunities and eligibility. No application may be submitted until entity status, registrations, PI eligibility, certifications and institutional representations are verified.

### Evidence desk - NotebookLM
Use the curated source set as a source-grounded audit layer. Notebook-generated synthesis is secondary evidence, never a substitute for reading the primary sources.

## Claim states
Every public claim must be tagged internally as one of:

- ESTABLISHED: supported by external peer-reviewed or otherwise authoritative evidence.
- REPRODUCED COMPUTATIONALLY: reproduced from frozen code/data in this repository or an archived artifact.
- REPORTED COMPUTATIONAL RESULT: present in a checkpoint but not yet independently rerun from a public artifact.
- INFERRED: interpretation consistent with data but not directly tested.
- CONJECTURE: mathematically or biologically plausible, explicitly unproven.
- PROSPECTIVE: preregistered prediction awaiting test.
- REJECTED: failed calibration, counterexample, replication or validation.

## Publication gate
A result enters the main README or Alfredo public science voice only after:
1. provenance is frozen;
2. the metric and estimator are specified;
3. at least one adversarial test has been attempted;
4. uncertainty or finite-sample limitations are stated;
5. novelty language has been checked against Lane A;
6. biological claims from simulations are not described as living-system discoveries.

## Prospective-study gate
Before any living-system result is seen, freeze:
- hypothesis and falsification criteria;
- inclusion/exclusion rules;
- primary endpoint;
- train/test partition;
- model and hyperparameter-selection protocol;
- perturbation-selection algorithm;
- random/equal-cost baseline;
- sample-size rationale;
- analysis code hash.

## Communication standard
Alfredo's public voice should be clear, restrained and visually polished. Structure:
1. one-sentence hook;
2. the scientific question;
3. what was actually done;
4. result with numbers only when reproducible;
5. limitation / what would falsify it;
6. next experiment;
7. link to public evidence.

No unqualified words such as "proved biology", "Nobel", "revolutionary", or "breakthrough" unless the evidence truly warrants them.

## Grant standard
No grant is listed as actionable without an official source, current deadline, award mechanism, eligibility, entity prerequisites, PI requirements and a named scientific fit. No submission or certification is made on Alfredo's behalf without verified factual fields and required attestations.

## Weekly checkpoint
Each checkpoint should contain:
- new findings;
- rejected findings;
- changed confidence;
- literature updates;
- reproducibility status;
- prospective tests;
- funding deadlines;
- communications released;
- next highest-information experiment.
